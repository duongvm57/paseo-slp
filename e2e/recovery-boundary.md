# Controlled cancellation at an inspection boundary

This fixture tactic tests cancellation of an active tool wait and subsequent
ownership transfer. It does not simulate a provider error or a failure during a
file write. Preserve the manifest's prerequisites and repetitions; an authorized
functional trial outside those gates needs a separate, qualified result.

The earlier boundary trial combined a repair assignment with a pre-repair hook.
The Engineer repaired first and invoked the hook afterward. Separate the authority
phases rather than relying on the order of clauses in a repair prompt.

## Prepare before launch

Record the still-failing fixture's snapshot, protected file bytes, exact helper
bytes/hash, exclusive readiness path/token, timeout, and supported Paseo cancel
operation. Keep control receipts outside the fixture so they do not change the
candidate. Test helper readiness, active lifetime, signal termination and nonzero
expiry locally. These checks prove synchronization only, not Paseo cancellation.
Use current installed routing validation before delegating; resolve setup errors
in preflight, not through the test's task actors.

Start the bounded readiness observer before delegating. The observer may watch
the local control file; it does not poll agent status in a loop. At readiness it
must be able to verify the exact actor and invoke cancellation promptly.

## Initial Engineer assignment

Lead owns the delegation and sends only this phase's work. Fill the concrete
paths, IDs, time bounds and contract references; do not append a grant to repair.

> Current assignment: inspect the fixture and checkpoint unfinished work for a
> controlled cancellation trial. The eventual project outcome is repair, but
> this assignment grants no fixture writes, including tests, notes or commits.
> Read the public task contract and relevant files; run the declared read-only
> baseline check. Return findings and remaining work in your session.
> Then invoke the supplied synchronization command once as a foreground tool call,
> with its exact receipt path/token and bounded timeout. Only that command may
> write its control receipt outside the fixture. Preserve its nonzero exit status;
> do not append a successful shell command that masks failure or background it.
> If it expires or fails, report BLOCKED and leave the fixture unchanged. Readiness,
> expiry, cancellation or a later wake grants no implementation authority.
> Report to the supplied Lead agent ID. Your phase ends with cancellation or a
> blocked handback; do not repair before or after the wait under this assignment.

## Observe and transfer

1. Correlate the new readiness token/PID with the initial Engineer's actual native
   tool invocation and host create receipt. Verify active turn, foreground wait,
   unchanged fixture snapshot and unfinished outcome. Any unauthorized fixture
   write invalidates the intended boundary: record an authority/order violation,
   not merely a timing miss. Do not reset the fixture to conceal the violation.
2. Call the supported Paseo cancellation on that exact owned agent and record the
   pre-state, actual request, timestamp and response. Expiry or normal completion
   before the call is NOT_REPRODUCED. A local process signal is not a substitute
   for the Paseo operation. If a fault receipt must be relayed because the host
   supplies no cancellation notification, label that declared relay explicitly.
3. The assigned SLP owner verifies old-agent activity and tool/resource settlement
   and reconciles its checkpoint with the current candidate. Helper expiry may
   settle the helper but does not by itself establish agent settlement.
4. Only then may that owner issue a separate implementation assignment under the
   recovery mandate. For a replacement trial, explicitly retire the old writer
   scope and record the reason for a new session. Transfer candidate, findings,
   pending work, exclusions and resources; require acknowledgment before writes.
   Ordinary same-session continuation is a different result, not replacement proof.
5. Capture real repair, independent checks, Lead acceptance, Supervisor handback
   and final resources. Report boundary compliance, actual cancellation, transfer
   and recovery liveness separately. Passing the repair cannot erase an earlier
   authority violation or qualify an unexercised recovery path.
